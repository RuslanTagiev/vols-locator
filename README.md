# 📦 ВОЛС-Локатор

Мобильный геоинформационный сервис (GIS/B2B) на React и TypeScript для автоматизации работы линейно-кабельных бригад связи и оперативного устранения аварий на оптических магистралях.

## 🎯 Бизнес-логика и архитектурное решение (Problem Statement)

### Ограничения существующих методов локализации (Проблема)
При возникновении аварий на протяженных участках ВОЛС первичные измерения оптическим рефлектометром (OTDR) производятся из узловых станций дежурной дислокации. Основная проблема этого подхода — **линейное накопление кумулятивной погрешности** измерения на больших дистанциях. Погрешность усугубляется температурными колебаниями, неоднородностью волокна и сложностью учета запасов кабеля.

В полевых условиях линейно-кабельные бригады вынуждены сопоставлять данные OTDR с паспортами трасс вручную. Локализация места повреждения осложняется необходимостью ручной привязки к железнодорожному пикетажу (км/ПК) и номерам опор. В условиях городской застройки или пересеченной местности ручной расчет критически увеличивает время простоя магистрали (MTTR) и приводит к финансовым потерям.

### Технологическое решение «ВОЛС-Локатор» (Value Proposition)
Приложение полностью устраняет проблему кумулятивной погрешности за счет **медиальной интерполяции внутри локального сегмента**:

1. **Динамический пересчет опорной точки:** Система уходит от сквозного расчета всей многокилометровой дистанции от измерительной станции. Алгоритм идентифицирует ближайшие к зоне инцидента реперные точки (оптические муфты/технологические запасы) с верифицированными географическими координатами.
2. **Автоматическая сегментация трассы:** На основе массива данных (`CableNode[]`) и цикла перебора пар точек приложение автоматически определяет конкретный межмуфтовый пролет, внутри которого находится повреждение.
3. **Математическое сокращение погрешности повива:** Поскольку кабель свит равномерно по всей длине, алгоритм рассчитывает точное место обрыва через **процентное соотношение (пропорцию) локального отрезка**. Относительный коэффициент внутри короткого пролета остается неизменным как в оптических, так и в физических метрах. Это математически исключает необходимость ручного или программного подбора коэффициента повива — он сокращается при делении внутри функции.
4. **Геовизуализация и навигация «последней мили»:** Интерактивный модуль на базе `React-Leaflet` рассчитывает точную координату инцидента на линии трека и выставляет маркер. Реализован бесшовный переход в картографические сервисы Яндекс для построения пешеходного или автомобильного маршрута непосредственно к точке обрыва (`rtt=pd`).
